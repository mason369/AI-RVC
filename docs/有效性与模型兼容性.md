# 有效性、参数与模型兼容性

接口与配置说明更新于 2026-09-06。已运行验证的模型、设备和入口列在“验证范围”中；发布版本见项目 Releases。

## RVC 模型边界

| 项目 | 支持范围 | 不符合时的行为 |
|---|---|---|
| 内容特征 | RVC v1 原生 256 维；v2 原生 768 维 | 未知维度报错，不截断、补零或降维 |
| HuBERT | v1 第 9 层经过原生学习投影；v2 第 12 层 768 维 | 使用与权重架构匹配的 HuBERT 特征 |
| 生成器采样率 | 模型原生 32、40、48 kHz | 其他架构需独立实现，不能只改配置数值 |
| F0 | 带 F0 与无 F0 的标准 v1/v2 架构 | 无 F0 模型禁止非零移调，界面禁用音高控件 |
| 说话人 | 以 `emb_g.weight` 的真实行数为准，ID 从 0 开始 | ID 越界时报错 |
| 权重 | 标准 18 项 RVC 配置、完整推理层与匹配形状 | 缺层、未知层、NaN/Inf、量化权重均拒绝；训练专用 `enc_q` 可省略 |
| FAISS | 同维度、已训练的 FlatL2/IVFFlat，完整有限值 FP32 向量 | 不接受量化、PCA 或其他索引类型；官方固定 K=8，至少 8 个向量；失败不跳过 |

文件名中的 `_v2` 不决定版本，以权重结构为准。没有索引时可使用模型，但必须显式设检索混合率为 0；UI 会根据模型文件禁用索引控件。正检索率不能被静默改为 0。

原生 256 维投影是 v1 训练架构的一部分，不是为了省显存把 v2 的 768 维压低。1024 维 ContentVec、自定义编码器、so-vits-svc、Seed-VC 等不是标准 RVC 权重，当前不承诺直接兼容。

### 角色清单与下载验收（2026-09-06）

181 个条目完整保留：178 个 Hugging Face 条目的配置文件已经通过远端仓库树核对；松浦果南与高咲侑的 Google Drive 文件已经实际下载、校验并推理。樱坂雫的原 Mega 链接实测返回 `ENOENT`，公开来源页仍是同一失效链接，尚无可核验替代权重。列表保留该条目，并显示核验日期与失败原因。

本地千歌、黛雅、花丸、鞠莉、东海帝王、善子、果南、高咲侑共 8 个角色，使用 5 秒真实音频、CPU FP32、检索率 0.5、RMVPE、说话人 0，各自完成当前与官方两路推理，16 路均为有限、非零、模型原生采样率的 Float32 WAV。它们覆盖实际 v1/256D/48k、v2/768D/40k、v2/768D/48k。未下载的 173 个条目没有权重级验收，远端文件存在不等于结构、音质或许可已经验证。

这里的两路指本地 fairseq `VoiceConversionPipeline` 与固定版官方 VC 引擎，不是两种完整翻唱模式。另对千歌 v1、黛雅 v2 补做 RTX 4070 Ti SUPER CUDA 验收，两引擎共 4 次通过；本地生成器为 FP32，官方日志显示 FP16。连同 CPU，本角色专项完成 20 次带索引音色转换，并非 20 次整曲分离与混音。

原始 Dia2 索引为 IVFFlat，`nprobe=1` 时 249 帧中的 5 帧无法返回完整 8 个近邻。当前/官方入口统一将全部原始 FP32 向量加载到内存 FlatL2，进行全量精确搜索；磁盘原索引不变。不补无效近邻、不降低维度、不量化、不关闭索引。精确相同向量单独按零距离规则加权，避免除零。全量检索可能增加 CPU 时间与内存，不能承诺等同旧近似搜索的性能。

文件选择要求明确：每个角色目录只有一个 `.pth` 和至多一个 `.index`；根目录可使用同名精确配对。多权重、多索引或模糊同名不任选一个。损坏模型仍列出失败状态，不能通过下载成功或导入成功的门槛。下载用独立暂存目录，校验通过再替换，旧目录保留 `-previous` 备份。

Google Drive 固定 `gdown==6.0.0`，支持公开大文件确认表单，不绕过分享权限或配额。Mega 使用 Megatools 作者发布的 `1.11.5.20250706` Windows/Linux x64 构建，下载包和程序均校验 SHA-256，随附许可证；这是当前查到的二进制发布版，不等同于最新源码版本。其他平台需已安装 `megatools`。认证/限流失败停止批量队列；来源失效明确失败，不切换成其他角色。

## 分离模型的“维度”

分离模型的 62/90 bands 与 RVC 的 256/768 内容特征不是同一个概念。

| 环节 | 默认权重 | 原生配置 |
|---|---|---|
| 人声 | Leap XE vocals | 90 bands |
| 纯伴奏 | 标准 Leap Instrumental | 62 bands |
| 主唱与带和声伴奏 | MVSep 9205 三模型 `avg_wave` | 每个子模型使用对应公开配置 |
| 去混响 | BS-RoFormer De-Reverb Stereo 22.5050 | 对应立体声权重与配置 |

各分离模型使用原生 band 配置；124-band 等缺少本项目可核验权重与配置的版本尚未支持。

当前选择标准 Leap Instrumental 的依据包含本地 30 秒受控混合物比较：audio-separator 0.47.0 下 SI-SDR 19.2844 dB，已移除的历史对照 PolarFormer 18.4565 dB。参考 stem 为模型生成的受控素材，并非录音室真值；这不能证明每首真实歌曲上都最优。没有参考 stem 的整曲仅提供信号诊断数据。

## 精度与输出

- 模型推理使用 FP32，或设备支持的 FP16；保留原生特征维度，不支持 INT8、INT4、FP8 量化模型。
- 分离输入统一为 44.1 kHz、双声道 Float32 WAV；MP3/FLAC/非标准 WAV 都明确解码，原文件不覆盖。分离器模型仍按其原生配置推理。
- 固定版官方 RVC 的网络、特征层和 DSP 保留；对整数输出编码及索引加载/加权块做严格匹配的运行时适配，返回原始浮点音频并使用上述精确检索。上游接口变更则停止，不修改 vendored 源码。浮点适配发生在整数编码之前。
- 参数复查另修正官方 F0 插值与清辅音保护的冲突：保留提取器原生的无声零值，再按标准 RVC 路径进行移调和 F0 编码。原固定版会把所有无声帧插值为正频率，使 `protect` 无法识别这些帧。此修正会改变含无声帧的转换结果，属于推理行为修复；不是音质分数或仅格式转换。适配严格匹配上游实现，源码目录与权重不改动。
- 离线转换在加载官方配置前固定 `RVC_CUDA_GRAPH=0`。变长片段各自重复预热并保留图私有内存池，会带来额外计算与显存压力；常规推理避免逐片段图预热及额外图内存。2026-09-05 的本机记录中，整曲 VC 及保存耗时 7.23 秒。
- UVR5 使用固定版模型直接推理，并对整数输出编码做同类适配，不经过上游会吞异常重试的批处理封装。源码 checkout 不修改。
- 中间音频和最终混音写 Float32 WAV。HuBERT 的 16 kHz 单声道输入是模型要求，不是成品采样率；RVC 输出保留模型原生采样率，混音采用两路中较高者。
- 用户已有 MP3 等有损源不可能恢复为原始无损录音。浮点保存是避免新增整数编码损失，无法恢复已有压缩损失。

## 参数适用条件

配置只允许 `language`、`device`、`weights_dir`、`output_dir`、`cover`；以 `configs/schema.py` 与仓库 `configs/config.json` 为准。JSON 值的类型、数值范围和未知键都会校验。

| 参数组 | 适用范围 |
|---|---|
| `pitch_shift` | 整数半音；API -24～24，当前 Web 控件 -12～12；仅带 F0 模型 |
| `index_rate` / API `index_ratio` | 0～1；Web 使用百分比；大于 0 必须有有效同维度索引 |
| `protect` | 0～0.5；官方路线仅 F0 模型且检索开启时有效，0.5 关闭 |
| `f0_method` | 默认官方入口支持 `rmvpe/pm/fcpe`；本地兼容入口支持 `rmvpe/pm/harvest/crepe`；只对 F0 模型提取音高。FCPE 安装依赖固定为 `torchfcpe==0.0.4`；本地入口不支持 DIO |
| `rms_mix_rate` | 0～1，0 关闭源响度包络匹配；内部转换为官方相反方向的系数 |
| `speaker_id` | 0～模型真实说话人数减 1，不使用固定 255 上限 |
| `demucs_model/shifts/overlap/split` | 仅 Demucs；参数错误会终止处理 |
| `uvr5_model/agg/format` | 仅 UVR5 VR `.pth`；agg 0～20，翻唱输出固定 WAV |
| `roformer_model` | 仅 RoFormer 分离；未知 ID 明确失败 |
| `karaoke_*` | 仅 Karaoke 开启时；当前完整翻唱只接入 `ensemble:mvsep_9205_avg` 的已定义输出合同 |
| `source_constraint_mode` | 当前路线使用；官方诊断路线关闭。`auto` 依赖实际去混响状态，`on` 要求预处理成功 |
| `silence_*` | 当前路线且 `silence_gate=true` 时使用；关闭时跳过静音门控 |
| 音量、混响、原主唱混入 | 用于混音；混响依赖缺失时报错 |

`speaker_id` 的配置初值会传入界面；超出所选模型范围时报错，不重置为 0。`use_official` 选择音色转换引擎，不改变显式选择的 UVR5 分离器；UVR5 始终使用固定版分离实现。PM 保留无声帧为 0，官方 FCPE 的静音门限也使用 FCPE 提取器，不更换算法。

`weights_dir` 用于模型管理表与 MCP 模型目录；角色下载、导入与翻唱选择使用固定的 `assets/weights/characters/`。`output_dir` 用于 Web 成品输出，直接 API/MCP 调用使用调用方指定的输出路径。关闭 Karaoke 或静音门限后，其下级参数只作为对应功能的配置保留，不执行相关处理。

`vc_pipeline_mode=current` 与 `use_official=true` 是默认组合：固定提交官方 RVC + 项目后处理。显式 `use_official=false` 才是本地 fairseq 兼容路线。`vc_pipeline_mode=official` 是诊断路线：UVR5 → 同一去混响模型 → 官方 VC，不执行 Karaoke、源约束或项目静音门限后处理；UI 禁用不适用项。

已移除的公共配置/控件：`hubert_layer`、默认链路 `filter_radius`、`singing_repair`、重复 `vc_preprocess_mode`、未被消费的旧 F0 混合/平滑/恢复参数、`reverb_reapply_strength`、顶层重复 VC 参数、无效 `paths/server` 等。迁移时不要把旧 JSON 整份覆盖回来。直接调用本地 `VoiceConversionPipeline.convert` 的 `filter_radius`、显式 `resample_sr` 仍有实现，不属于默认 Web/完整翻唱/MCP 参数。

## MCP

本地入口为 `python -u -m rvc_mcp.server`，工作目录设为仓库根目录，使用项目虚拟环境 Python。旧 `mcp` 包名与官方 SDK 冲突，已经移除。

| 工具 | 实际功能 |
|---|---|
| `list_voice_models` | 返回模型清单和唯一 `id`，同名文件不猜测选择 |
| `convert_voice` | 单独的人声音色转换，**不包含**分离或整曲混音；输出 WAV |
| `download_base_models` | 显式准备基础模型，失败返回错误 |
| `get_model_status` | 检查模型及固定源码的本地状态 |

先读取模型清单，再把返回的 `id` 填入 `model_name`。只有名称唯一时才可直接用短名。所有工具拒绝额外参数。数值推理进程与 stdio 服务分离，避免 Windows 原生 DLL 初始化与读取线程相互阻塞。

示例转换参数（路径替换为实际文件）：

```json
{
  "input_path": "D:/Music/lead.wav",
  "output_path": "D:/Download/converted.wav",
  "model_name": "characters/dia_v2/Dia2.pth",
  "pitch_shift": 0,
  "index_ratio": 0,
  "rms_mix_rate": 0,
  "protect": 0.33,
  "speaker_id": 0,
  "f0_method": "rmvpe"
}
```
