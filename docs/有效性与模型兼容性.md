# 模型兼容性与参数说明

本文说明 AI-RVC 支持的模型架构范围、运行精度策略、配置参数适用条件以及 MCP 本地服务接口。

## RVC 模型兼容性

| 项目 | 支持范围 | 异常处理 |
|---|---|---|
| 内容特征维度 | RVC v1 原生 256 维；RVC v2 原生 768 维 | 未知维度直接报错，按实际权重架构校验 |
| HuBERT 特征 | v1 第 9 层原生投影；v2 第 12 层 768 维 | 按权重架构自动匹配特征维度 |
| 生成器采样率 | 支持 16–192 kHz 整数采样率（常见 32 / 40 / 48 kHz） | 结合完整网络权重形状核对 |
| 音高引导 (F0) | 支持带 F0 与无 F0 标准 v1/v2 模型 | 无 F0 模型自动禁用音调偏移控件 |
| 多说话人 ID | 按 `emb_g.weight` 实际行数确定有效范围（从 0 开始） | ID 越界时报错 |
| 生成器架构 | 标准 RVC v1/v2、Applio HiFi-GAN、MRF HiFi-GAN、RefineGAN | 缺层、形状异常、非有限值或低比特量化权重均报错 |
| FAISS 索引 | 同维度已训练的 `FlatL2` / `IVFFlat`，完整有限 FP32 向量 | 官方入口固定 `K=8`（至少 8 个向量），不兼容索引报错 |

- 模型版本依据实际权重结构识别，无索引模型需将检索比率设为 `0%`（界面自动禁用对应滑块）。
- 角色目录支持单 `.pth` + 单 `.index` 精确配对，同时兼容标准的 `trained_*.index` + `added_*.index` 双索引包（确认前者为零向量训练模板后自动选用后者进行推理）。
- 检索阶段统一将全部原始 FP32 向量加载到内存 `FlatL2` 执行精确搜索，避免稀疏 IVF 索引返回无效近邻，同时保留磁盘原索引文件并支持中文路径。
- 下载器使用 `gdown==6.0.0` 处理 Google Drive 公开文件，并在 Windows/Linux x64 自动准备带 SHA-256 校验的 Megatools；下载和导入均先在暂存目录校验通过后再原子替换。

## 默认分离与去混响模型

| 环节 | 默认权重 | 配置规格 |
|---|---|---|
| 人声分离 | Leap XE vocals | 90 bands |
| 纯伴奏分离 | BS-RoFormer Leap Instrumental | 62 bands |
| 主唱与带和声伴奏 | MVSep 9205 三模型 `avg_wave` | 按各子模型官方 YAML 配置运行 |
| 去混响 | BS-RoFormer De-Reverb Stereo 22.5050 | 立体声权重与配置 |

## 精度与音频输出策略

- **分离与解码**：输入统一解码为 44.1 kHz 双声道 Float32 WAV；所有 RoFormer 分离模型保持 FP32 常规推理。
- **RVC 与 RMVPE 精度选择**：共用精度选择器，根据权重原生精度与实际 CUDA 显卡型号共同决定运行精度。支持 Tensor Core 的 NVIDIA 显卡保留原生 FP16；GTX 16 系列（含 GTX 1660 SUPER）即使报告 SM 7.5，仍遵循官方规则将 FP16 权重无损升为 FP32 在 CUDA 上运行，避免半精度 F0 异常；CPU、非 NVIDIA 后端及其他设备自动将 FP16 / BF16 升为 FP32；FP32 / FP64 权重保持原生精度。
- **连续 F0 与清辅音保护**：连续 F0、激励频率与相位累积使用 FP32 或更高精度；保留提取器原生的无声零值标记，使清辅音保护参数准确生效，并拒绝 `NaN` / `Inf` / 负频率异常输出。
- **长歌曲拼接与浮点输出**：长音频按绝对采样坐标裁剪上下文并采用短互补交叉淡化拼接；离线转换固定关闭 CUDA Graph 避免变长片段显存膨胀；中间文件、RVC 输出与最终混音全程保留浮点 WAV（FP32 / FP64 DOUBLE）。

## 参数适用条件

配置文件 `configs/config.json` 采用严格字段白名单校验（顶层允许 `language`、`device`、`weights_dir`、`output_dir`、`cover`），未知字段或非法数值会明确报错。

| 参数 | 适用条件与说明 |
|---|---|
| `input_mode` | `song`（整曲翻唱，默认）或 `vocals`（纯人声转换） |
| `pitch_shift` | 整数半音（API `-24` 至 `+24`，Web 界面 `-12` 至 `+12`），适用于带 F0 模型 |
| `index_rate` / `index_ratio` | `0–1`（Web 界面 `0–100%`），大于 0 时需要有效同维度索引 |
| `protect` | `0–0.5`（`0.5` 关闭），适用于带 F0 且启用索引检索的推理 |
| `f0_method` | 官方入口支持 `rmvpe` / `pm` / `fcpe`（需 `torchfcpe==0.0.4`）；本地兼容入口支持 `rmvpe` / `pm` / `harvest` / `crepe` |
| `rms_mix_rate` | `0–1`（`0` 关闭），控制转换人声对源人声音量包络的贴合程度 |
| `speaker_id` | `0` 至模型真实说话人数减 1 |
| `karaoke_*` | 仅在开启和声分离时生效，默认使用 `ensemble:mvsep_9205_avg` |
| `source_constraint_mode` | `auto` / `off` / `on`，适用于标准翻唱流程（官方 RVC 路线自动关闭） |
| `vc_pipeline_mode` | `current`（标准翻唱，含和声分离与人声后处理）或 `official`（经典 UVR5 + 官方 VC 诊断路线） |
| `silence_*` | 仅在 `silence_gate=true` 且使用标准翻唱路线时生效 |
| `demucs_*` / `uvr5_*` / `roformer_model` | 按所选 `separator` 后端生效 |

## MCP 本地服务

AI-RVC 提供基于 Model Context Protocol (MCP) 的本地音色转换服务，在仓库根目录使用项目虚拟环境启动：

```bash
python -u -m rvc_mcp.server
```

| 工具名 | 功能 |
|---|---|
| `list_voice_models` | 列出本地可用声线模型及唯一 `id` |
| `convert_voice` | 执行人声音色转换（输出 WAV，输入为干声） |
| `download_base_models` | 准备基础运行模型 |
| `get_model_status` | 查看基础模型、分离模型与官方运行组件状态 |

调用 `convert_voice` 示例参数：

```json
{
  "input_path": "/path/to/lead.wav",
  "output_path": "/path/to/converted.wav",
  "model_name": "characters/dia_v2/Dia2.pth",
  "pitch_shift": 0,
  "index_ratio": 0.5,
  "rms_mix_rate": 0,
  "protect": 0.33,
  "speaker_id": 0,
  "f0_method": "rmvpe"
}
```

```bash
# 全量单元测试
python -m unittest discover -s tests -v

# 模型合同与翻唱链路核验（需准备示例音频与权重）
python tools/verify_feature_contracts.py --input /path/to/lead.wav --output outputs/rvc_contracts --local --mcp
python tools/verify_cover_runtime.py --input /path/to/song.mp3 --output outputs/rvc_cover
```
