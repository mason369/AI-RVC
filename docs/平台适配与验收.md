## Issue #5：Gradio 路径漏洞的适用范围

[Gradio 官方公告 CVE-2026-28414](https://github.com/gradio-app/gradio/security/advisories/GHSA-39mp-8hj3-5c49)针对 Windows 与 Python 3.13 及以上的组合，修复版本为 Gradio 6.7.0。[Python 3.13 官方文档](https://docs.python.org/3.13/library/os.path.html#os.path.isabs)确认，单斜线开头的 Windows 路径在该版本起不再被 `os.path.isabs` 判为绝对路径。

本项目安装器、便携包和 Docker 固定 Python 3.10；Docker 实际运行 Linux。本次 Windows Python 3.10.11 / Gradio 5.49.1 实测中，根相对路径仍判为绝对路径，三种越界路径被 `safe_join` 拒绝；仅针对本次自建无敏感内容的测试文件发起本地 HTTP 请求，返回 403，文件未暴露。当前发行环境不满足该公告的触发组合。

Gradio 仍为 5.49.1，本版没有升级到 6.7.0；上述检查不代表所有依赖都没有漏洞。Windows 源码部署须使用项目规定的 Python 3.10，不应自行改为 3.13 及以上。Issue 保留以跟进报告中未列明的其他漏洞编号及后续 Gradio 大版本兼容验证。

- 已按 [PyInstaller 的 NVIDIA 收集方式](https://github.com/orgs/pyinstaller/discussions/8202)补齐全部带版本号动态库及插件，保持 [NVIDIA 要求的 NVRTC 与内置库版本配对](https://docs.nvidia.com/cuda/nvrtc/#nvrtc-builtins-library)。使用实际构建环境核验 **45/45** NVIDIA 动态库可被收集，原包漏收的 **23** 项均纳入。

## 不降质的处理原则

默认仍使用 Leap XE 90 人声、标准 Leap Instrumental 62 纯伴奏、MVSep 9205 三模型 `avg_wave` 和 Stereo De-Reverb 22.5050。没有换成小模型、减少模型数量、关闭检索或跳过去混响。

六个 RoFormer 保持 FP32，关闭 autocast、native FP16 和 compile，重叠/批大小继承各自 YAML：Leap XE 2/2、Leap Instrumental 2/2、Gabox 2/6、Frazer 4/2、Anvuew 4/2、De-Reverb 2/2。RVC/HuBERT 保留固定版官方的既有设备精度策略：本机 CUDA 为 FP16、CPU 为 FP32；本次没有把原本的 FP32 转换步骤改成 FP16。中间文件和七类最终音频继续使用 Float32 WAV。

这些约束和真实输出校验能证明没有采用降低精度或简化流程的适配方式，不能证明所有歌曲的听感必然更好。0.44.1 与 0.47.0 的同一首约 241 秒歌曲均已保留用于试听；上游重叠计算修正会改变数值结果，输出不应要求逐位相同。

**已按用户确认接受这项微小差异，继续整合升级。** 同一 30 秒受控样本中，Leap SI-SDR 从 0.44.1 的 19.3401 dB 变为 0.47.0 的 19.2844 dB，差值 -0.0557 dB；保留测量事实，不再以此阻挡本次升级。分离保持 FP32 和模型原有参数；单一样本不能证明所有歌曲听感都会提升。升级前后试听成品仍保留，正式发行状态见上述 Release。

## WSL 资源错误复查

此前 `Wsl/Service/CreateInstance/CreateVm/HCS/0x800705aa` 阻止启动；本轮先恢复启动并完成真实 CPU 默认链，证明该用户态依赖和推理流程能够运行。

后续 Windows 便携包验收期间，同一系统错误再次出现。当时本次验收进程占用约 7.92 GiB 私有内存，系统剩余提交空间约 12.7 GiB；两个既有 Web 服务及其他应用仍在运行。确认验收任务结束、队列为空后关闭本次临时验收程序，WSL 随即启动，当时的 330 项测试通过。导入隔离修正后还单独完成一次真实 CPU RVC 转换，输出为 40 kHz、199200 帧、单声道 Float WAV。

Docker 验收前，用户明确允许暂停占用约 10.49 GiB 的 18648 预览。随后还确认了另一项独立条件：手动 WSL Engine 中的 systemd 服务不会保持发行版存活，参见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/wsl/systemd)。本轮以前台 Compose 会话运行；Windows 长期使用推荐 Docker Desktop 的 WSL2 后端。该生命周期条件与之前的内存错误分别记录。

这是资源压力相关的复现与恢复证据，不能称为系统问题永久消失。本轮未改 .wslconfig、分页文件、其他应用或系统并发设置。长期同时运行多套大模型服务，需要按实际峰值为 Windows 与 WSL 预留内存和提交空间，并另做对应负载验收；不能靠自动重启或缩减模型掩盖错误。

## 本轮修正的遗漏

1. **依赖逐个安装破坏已装版本。** Colab 实际安装时 MCP 2.x 带入的 Pydantic 与 Gradio 5.49.1 冲突。安装器改为一次解析完整 requirements，精确保留已选 torch/torchvision/torchaudio 构建，MCP 约束为 >=1.26,<2。已装齐但 pip check 不通过也会修复依赖并重查，失败明确停止。
2. **GPU 安装组合不完整。** 三个 PyTorch 包一次选定版本；专用 ROCm/XPU/DirectML 栈不被通用安装覆盖。PyTorch 2.11 新安装采用受支持的 cu126/cu128 索引；Blackwell 要求驱动支持 CUDA 12.8，老架构和混合显卡组合明确检查。已安装且兼容的本机 cu128 保留。依据 [PyTorch 官方版本表](https://pytorch.org/get-started/previous-versions/)及[版本说明](https://github.com/pytorch/pytorch/releases)。
3. **音频库遗漏。** Apple Silicon 对齐上游 torch>=2.13 和 Homebrew libsamplerate；Linux/WSL/Space/打包系统依赖补齐 libsamplerate0。参见 [audio-separator 0.47.0 依赖](https://github.com/nomadkaraoke/python-audio-separator/blob/v0.47.0/pyproject.toml)及[上游 ARM 音频库问题](https://github.com/nomadkaraoke/python-audio-separator/issues/293)。
4. **模型校验缓存误认损坏文件。** 已实际复现同长度、同修改时间覆盖后复用旧校验结果。基础权重重新校验内容；角色权重和索引的检查缓存以内容 SHA-256 为键，损坏、替换及修复均正确识别，不只检查文件存在、时间或大小。
5. **便携包依赖 Git 仓库结构。** 实际包缺少 Git 必需的空目录，原校验无法工作。冻结程序改为逐一验证固定 revision 的 495 个官方跟踪文件的规范化 SHA-256，拒绝损坏和额外 Python 代码；不要求用户安装 Git。源码模式继续检查 Git revision 和真实修改。
6. **便携包资源和导入路径缺失。** 实际启动发现 safehttpx/groovy 的 version.txt 漏收集，已同步 spec 和发行工作流；VC/UVR5 现在显式绑定官方 infer/configs/i18n/tools 包，保留 PyInstaller 的第三方依赖搜索路径。新增回归覆盖同名包冲突和归档依赖。依据 [Python 导入 API](https://docs.python.org/3.10/library/importlib.html)和 [PyInstaller 运行时说明](https://pyinstaller.org/en/stable/runtime-information.html)。
7. **测试写死 Windows 文件名。** Linux 实跑发现 FFmpeg 夹具使用 .exe，已按平台生成名称。运行时本身的跨平台选择没有降级。
8. **既有同步继续回归。** pip 24.0 / setuptools 69.5.1、fairseq 0.12.2、HF CPU 完整依赖、原生 XPU 检测、Windows/WSL CRLF 规范化校验、七类有效音频及 DirectML 加载前拒绝继续保留。HF 安装顺序依据 [官方文档](https://huggingface.co/docs/hub/spaces-dependencies)。
